# Аудит frontend/backend

Дата проверки: 2026-05-08.

## Проверено

- Backend: полный pytest, flake8.
- Frontend: production build, unit tests в headless Chromium.
- API: `scripts/api_smoke.py` по GET-эндпоинтам из OpenAPI через `http://127.0.0.1:4200/api`.
- Browser smoke: вход тестовым пользователем и переход по основным вкладкам.

## Что исправлено сразу

- Убран битый переход `Профиль` на несуществующий route.
- Список филиалов в левом меню теперь берется из `/api/admin/shops`, а не из захардкоженных данных.
- Бейдж заказов в левом меню теперь берет счетчик через `/api/orders/`, а не показывает фиктивное число.
- `OrdersService` получил метод `getOrdersPage`, чтобы компоненты могли работать не только с массивом, но и с пагинацией backend.
- Нестабильный backend-тест задач отвязан от времени запуска около границы дня.

## Закрыто после аудита

- Добавлен базовый экран `/profile`: данные сотрудника, текущий филиал, статус доступа и смена пароля через `/api/auth/change-password`.

## Нужно доделать

### P0

1. **Задачи**
   Backend поддерживает задачи, шаблоны, создание из шаблона, редактирование и комментарии: `/api/tasks/`, `/api/tasks/templates`, `/api/tasks/create-from-template/{template_id}`, `/api/tasks/{task_id}/comments`. Frontend сейчас в основном показывает список/статусы; создание задачи, карточка задачи, редактирование, комментарии и шаблоны не доведены до рабочего сценария.

2. **Финансы**
   Backend сейчас закрывает только платежи по заказам и retail-продажам: `/api/finance/order/{order_id}/create`, `/api/finance/sales/{sale_id}/pay`. Frontend показывает финансовый dashboard, но расходы, транзакции, кассы, методы оплаты, возвраты и полноценный журнал движения денег не имеют нормальной backend-модели/API.

3. **Склад**
   Backend богаче frontend: есть приемки, движения склада, штрихкоды, быстрый товар, POS-продажи, списания/корректировки, подсказки дозакупки. Во frontend пока не хватает списка заказов поставщику, приемки поставки, карточки/редактирования товара, управления штрихкодами, сканирования, retail sale/POS и нормальной модалки корректировки остатков.

4. **Документы и уведомления по заказу**
   В деталях заказа `printReceipt()` и `sendNotification()` все еще не являются полноценными сценариями. Документы backend есть для retail sale receipt, но нет законченного сценария печати/отправки документов по сервисному заказу.

### P1

5. **Заказы**
   Нужно расширить UX статусов: при клике на статус вроде `Выдан` открывать контекстную модалку с оплатой, финальной суммой, комментарием и историей, а не просто менять статус. Также стоит связать ремонтные этапы, согласования и audit/status history в один понятный workflow.

6. **Отчеты**
   Dashboard/export работают, но frontend не использует `/api/reports/generate/{template_id}` и `/api/reports/export/{report_id}` как полноценный конструктор отчетов. Нужны шаблоны, история сформированных отчетов и понятные статусы экспорта.

7. **Уведомления**
   REST-список и mark-read работают. WebSocket-код во frontend есть, но реальный backend WS-канал в OpenAPI не виден; нужно либо добавить realtime-канал, либо отключить/упростить reconnect-логику, чтобы не было ложного ожидания real-time.

8. **Лояльность и внешний клиентский сервис**
   Backend для loyalty и интеграции с внешним клиентским сервисом есть. В основном CRM-интерфейсе нет нормальной вкладки по карте клиента: баллы, награды, история транзакций, начисление/списание из заказа. Клиентская часть вынесена в отдельный сервис и синхронизируется через `/api/client-sync/*`.

9. **Администрирование и настройки**
    Базовые users/roles/shops/settings есть. Нужно довести UX прав: матрица permissions по ролям, проверка удаления сущностей, смена пароля сотрудника, настройки магазина/организации и понятные ошибки при конфликте данных.

### P2 / техдолг

10. **Профиль**
    Базовый экран профиля готов. Отдельно можно добавить загрузку аватара, редактирование своих контактных данных и список всех доступных филиалов без привязки к admin API.

11. **SCSS budgets**
    Angular build проходит, но несколько component SCSS превышают budget 8 KB. Это не ломает сборку, но стоит разнести повторяющиеся паттерны в общие стили.

12. **Ошибки в UI**
    В компонентах остаются `console.error` без единого пользовательского error-state. Нужно привести ошибки загрузки к общим empty/error/retry состояниям.

13. **API smoke**
    Скрипт проходит live API, но пропускает loyalty без настроенной программы и endpoints с отсутствующими ids. Нужны seed-данные для retail sale receipt, loyalty и sync-сценариев внешнего клиентского сервиса.

14. **Backend warnings**
    В тестах остаются deprecation warnings: `datetime.utcnow()` и deprecated tuple responses Django Ninja. Их стоит закрыть отдельно, пока они не стали ошибками при обновлении зависимостей.
